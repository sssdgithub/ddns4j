# 00 — 定位、原则、术语与边界

## 1. 定位

Foundation 是**通用插件平台**，不是某个业务系统。它提供：

- 插件的发现、装配、生命周期与依赖管理；
- 服务注册与解析（按能力而不是按实现）；
- 统一 Endpoint 模型（边缘/桌面/移动/中继）与接入协议；
- 控制台、身份治理、审计、包分发。

业务（如 ddns4j）以**应用包**形式接入：一组服务端插件 + 控制台页面 + 端点模块 + 默认配置。

## 2. 设计原则

| # | 原则 | 含义 | 违反的代价 |
|---|---|---|---|
| P1 | 一切皆插件 | 服务端能力、控制台扩展、端点能力统一 manifest | 出现第二套扩展机制，生态分裂 |
| P2 | 制品与实例分离 | Plugin 是包，Module 是实例 | 升级/回滚/多实例无法表达 |
| P3 | 副作用可逆 | 注册必须返回 disposer，卸载 LIFO 回滚 | 泄漏、幽灵行为、无法热更新 |
| P4 | 依赖声明式 | 用 `requires` 表达依赖，运行时装计算激活状态 | 启动顺序靠人编排，故障级联不可控 |
| P5 | 内核最小 | 内核不含业务概念；业务只在应用包 | 平台被单一业务绑架 |
| P6 | 能力优先于实现 | 消费方按 capability/service 查找，不 import 实现 | 无法替换、无法多实现 |
| P7 | 端点统一 | 边缘/桌面/移动/中继都是 Endpoint，差异由 profile 表达 | 每来一种端就加一套协议 |
| P8 | 状态双写 | 每个可下发对象都有 desired 与 reported | 无法回答"设备实际应用了什么" |
| P9 | 规范先于实现 | 契约用 JSON/HTTP/YAML 描述，语言无关 | 实现绑死语言，无法多语言生态 |
| P10 | 默认安全 | 不托管用户凭据；Endpoint 使用最小权限 Token | 一次泄露摧毁信任 |

## 3. 术语

| 术语 | 定义 |
|---|---|
| **Foundation Host** | 运行插件内核、控制台 API、治理能力的宿主进程 |
| **Plugin** | 可分发的制品：一份 manifest + 一个入口，`kind` 为 `server` / `endpoint` / `app` |
| **Module** | Plugin 的部署实例：部署在宿主上或某个 Endpoint 上，持有自己的配置与 desired/reported 状态 |
| **App（应用包）** | 聚合型 Plugin：服务端插件 + 控制台页面 + 端点模块 + 默认配置 |
| **Endpoint** | 被纳管的端：`edge` / `desktop` / `mobile` / `relay` profile；注意与 Node.js 无关 |
| **Profile** | Endpoint 的角色档案，决定可用能力与生命周期约束 |
| **Capability** | 能力描述（如 `dns.update`、`ip.resolve`、`ui.page`），与具体实现解耦 |
| **Service** | 运行时提供的具名能力实例，由某个 Module 提供，可被替换 |
| **Effect** | 一次可逆的副作用注册（监听器、路由、线程、缓存、MBean…） |
| **Inject** | 模块声明的服务依赖；齐备才激活，变化则重算 |
| **Scope** | 服务解析的作用域（继承/隔离/拦截） |
| **Twin** | desired/reported 双状态文档，可挂在 Endpoint 或 Module 上 |
| **Package** | 可分发的字节包：`server-plugin` / `endpoint-package` / `app-bundle` / `config-bundle` |
| **Channel** | 发布通道：`stable` / `beta` |
| **Tenant** | 治理隔离单元；Core 单租户，Enterprise 多租户 |

## 4. 运行时分层

```
┌──────────────────────────────────────────────┐
│ 接入层  HTTP API · Endpoint 协议 · SDK · Webhook│
├──────────────────────────────────────────────┤
│ 治理层  身份 · 角色 · 租户 · 审计 · 配额        │
├──────────────────────────────────────────────┤
│ 控制面  控制台 · 应用/模块/插件/包 · 配置 · 编排 │
├──────────────────────────────────────────────┤
│ 内核    Contract · Runtime · Scope · Assembly │
└──────────────────────────────────────────────┘
```

依赖方向只允许自上而下；内核不得引用控制面与治理层的任何类型。

## 5. 边界（v1 明确不做）

1. 不做进程级插件隔离（同宿主进程内，恶意插件可读环境变量）。
2. 不做分布式调度与多集群。
3. 不做内建计费、发票、支付。
4. 不托管用户的第三方云厂商凭据。
5. 不定义 UI 组件库；控制台只定义信息架构与权限映射。
6. 不实现插件市场交易；v1 只定义包与通道。
7. 不把"语言/运行时"当平台概念：Rust 只是 edge profile 的默认实现。

## 6. 质量目标（规范建议值）

| 指标 | 目标 | 测量场景 |
|---|---|---|
| 内核启动（无业务插件） | ≤ 3s | 参考实现，冷启动到 `/readyz` 200 |
| 单个模块激活 | ≤ 200ms | 不含模块自身初始化 |
| 卸载回滚 | 连续 100 次重载无残留 effect | 参考实现压测 |
| 控制面 API P95 | ≤ 200ms | 本地单机，不含 Endpoint 网络 |
| Endpoint 心跳 | 30s ± 20% 抖动 | 离线判定 3 个周期 |

> 以上为建议值，参考实现必须在 `07-minimal-loop.md` 记录实测。
